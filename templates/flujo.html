Flujo de trabajo

El servicio que estás viendo es el resultado del pipeline. El código vive en Git. Cada cambio propuesto se prueba antes de publicarse.

  1. Extracción

    scraper.py pide el HTML de Books to Scrape con requests, lo interpreta con BeautifulSoup y guarda título, precio en libras, disponibilidad, calificación y enlace. Entre páginas espera un segundo. Si la página falla o el precio no es válido, la ejecución se detiene.

  2. Integración continua

    GitHub Actions ejecuta pytest en Ubuntu cuando hay un push o un pull request hacia main. Las pruebas usan HTML local: no visitan el sitio durante la validación.

  3. Entrega continua

    Render publica la rama main solo cuando el check de GitHub Actions queda en verde. Un pull request no se despliega.

  4. Servicio

    Render ejecuta python iniciar.py. Gunicorn escucha el puerto que asigna la plataforma y /salud confirma que el catálogo cargó.
